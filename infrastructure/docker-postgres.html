Docker & PostgreSQL in MyCompass

What Docker is, how our database runs inside it, how to check it's alive, how to view it visually, and how Spring Boot talks to it.

1. What is Docker, in simple words?

Docker lets you run a program (like PostgreSQL) inside an isolated, self-contained "box" called a container — without installing that program directly on your Mac. The container includes everything the program needs (the exact OS libraries, the exact PostgreSQL version) already packaged up, so it behaves identically on any machine that runs Docker.

Think of it like a shipping container: whatever is packed inside it works the same whether it's on a truck, a ship, or a train — the outside world doesn't need to know or care what's inside.

2. Why we run Postgres in Docker instead of installing it directly

  • No messy local install — no fiddling with Homebrew services, version conflicts, or leftover config files on your actual Mac.
  • Fully disposable — if the database gets into a bad state, we just delete the container and start a clean one in seconds.
  • Matches real-world practice — production systems almost always run databases in containers, so this is realistic practice, not a shortcut.
  • One shared definition — the exact same docker-compose.yml file guarantees anyone running this project gets an identical database setup.

3. How it's set up in this project

The file mycompass-backend/docker-compose.yml describes the database container:

services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: mycompass
      POSTGRES_USER: mycompass
      POSTGRES_PASSWORD: mycompass
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
LineMeaning
image: postgres:16Use the official PostgreSQL version 16 image from Docker Hub.
POSTGRES_DB / USER / PASSWORDCreates a database named mycompass with a login of the same name/password, the first time the container starts.
ports: "5432:5432"Maps the container's internal port 5432 to port 5432 on your Mac — this is the part that lets your app "see" the database as if it were local.
volumes: pgdata:...Stores the actual database files outside the container, in a Docker-managed volume, so your data survives even if the container is removed and recreated.

4. Starting, stopping, and verifying the instance

Run these from inside the mycompass-backend folder:

# Start the database in the background
docker compose up -d

# Check it's listed as "Up"
docker compose ps

# Check Postgres itself is ready to accept connections
docker exec mycompass-backend-postgres-1 pg_isready -U mycompass

# View live logs (useful if something looks wrong)
docker compose logs -f postgres

# Stop the container (data is kept, since it's in the volume)
docker compose down

# Stop AND delete all data (careful — full reset)
docker compose down -v
Note: Docker Desktop (the app) must be running before any docker command works. If a command says it can't connect to the daemon, open the Docker Desktop app first and wait for it to fully start.

5. Viewing the database in a UI

Running SQL by hand in a terminal works, but for actually looking at tables and rows, a GUI client is much easier. For Mac, the simplest options are:

  • TablePlus (recommended) — clean, native Mac app, free tier is enough for this project.
  • DBeaver — free, cross-platform, more features than you'll need but works well.
  • pgAdmin — the official Postgres GUI, browser-based, a bit heavier.

Whichever you pick, create a new PostgreSQL connection with these details (same as in application.properties):

FieldValue
Hostlocalhost
Port5432
Databasemycompass
Usermycompass
Passwordmycompass

Once connected, you'll be able to browse tables, run queries, and see the rows your Spring Boot app creates in real time.

6. How Spring Boot actually connects to the Docker-based Postgres

This is the part that confuses people at first: the app isn't "talking to Docker" directly — it just connects to localhost:5432 exactly like it would for any normal, non-containerized Postgres install. The Docker port mapping from step 3 is what makes that possible.

Spring Boot app (running directly on your Mac) │ │ JDBC connection to localhost:5432 ▼ Your Mac's port 5432 ──────────────▶ Docker maps this to the container │ ▼ Postgres process running INSIDE the container │ ▼ Data files stored in the "pgdata" Docker volume

The connection details are in src/main/resources/application.properties:

spring.datasource.url=jdbc:postgresql://localhost:5432/mycompass
spring.datasource.username=mycompass
spring.datasource.password=mycompass

Spring Boot has no special "Docker awareness" — as far as it's concerned, it's just a normal PostgreSQL server sitting at that host and port. Docker's job ends at exposing port 5432 on your machine; everything from there on is a completely ordinary JDBC connection, same as it would be for any Postgres install.

Order matters: the Postgres container must already be running (docker compose up -d) before you start the Spring Boot app — otherwise the connection attempt fails immediately since there's nothing listening on port 5432 yet.
